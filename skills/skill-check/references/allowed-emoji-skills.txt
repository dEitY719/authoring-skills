# Skills permitted to contain emoji (one key per line).
# `#` comments and blank lines are ignored.
#
# ## Adding an entry
#
# 1. The key is `<plugin>:<skill>`, where `<plugin>` is the `name` field in that
#    repo's `.claude-plugin/plugin.json` and `<skill>` is the SKILL.md directory
#    basename. Never a bare skill name: `create` resolves to three different
#    skills in three different repos (gh-issue, gh-pr, packaging), so a bare key
#    silently exempts skills that never asked for it.
# 2. The rationale comment is mandatory. Name *which* glyphs and *why* they are
#    subject matter rather than decoration.
# 3. This file exempts a skill from the `skill-check` **rubric** only. CI is a
#    separate gate with a separate mechanism: add the path prefix to
#    `allow-emoji-paths` in that repo's `.github/workflows/validate.yml`. Both
#    are required; neither implies the other. That split is what made the
#    pre-split key breakage invisible for so long.
#
# Detection range and key resolution are specified in `checks.md` (Check 11).
